# tailwinds.cloud

Marketing site for **Tailwinds Cloud Technologies**, a remote-first, cross-border AI consulting and software team based in Windsor, Ontario, and Detroit, Michigan.

It's a one-page Next.js 16 site, styled with Tailwind CSS v4 and exported as fully static HTML. It runs on GitHub Pages or Google Cloud.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # fetches the TLDR feed, then writes the static site to ./out
npm start          # serves ./out locally
```

## Project layout

| Path | What it is |
| --- | --- |
| `src/app/page.tsx` | All page content and copy (services, approach, FAQ and more). |
| `src/lib/site.ts` | Business name, phone, emails and URL. Change contact details here. |
| `src/components/` | Header, TLDR insights feed, icons and section headings. |
| `src/data/tldr.json` | Latest TLDR AI and TLDR Dev issues. Generated by `scripts/fetch-tldr.mjs`. |
| `src/app/favicon.ico`, `icon.png`, `apple-icon.png`, `opengraph-image.png` | Favicons and social image. Generated, don't edit by hand. |
| `public/brand/`, `public/icons/` | Web-sized logos (WebP/PNG) and PWA icons used by the site. Generated. |
| `assets/images/` | **Source of truth:** the brand artwork PNGs. |
| `assets/png/` | Full-size transparent, cropped PNG masters exported from `assets/images/`. Generated. |
| `scripts/brand/` | `export-assets.mjs` turns the artwork into everything above. |

## Brand assets

The artwork in `assets/images/` is 2000px PNGs on a white square, so it isn't served directly. `npm run brand:export` removes the white background, crops each logo and writes:

| Source (`assets/images/`) | Output (`public/brand/`) | Use |
| --- | --- | --- |
| `Primary horizontal logo.png` | `logo-horizontal.webp` (+ `.png`) | Header; primary logo on light backgrounds. The PNG is used in structured data. |
| | `logo-horizontal-white.webp` | Footer; reversed logo on navy or dark backgrounds. |
| `Compact horizontal logo.png` | `logo-compact.webp` | Tight horizontal spaces (email signatures). |
| `Stacked logo.png` | `logo-stacked.webp` | Square-ish spaces (social profiles, signage). |
| | `icon.webp` | Cloud-sail mark on its own (cut from the stacked logo); hero card and favicons. |
| `Monochrome emblem.png` | `emblem-mono.webp`, `icon-white.webp` | One-colour mark; the white version is the contact-panel watermark. |
| `Circular emblem.png` | `emblem.webp` | Circular badge (stickers, avatars). |
| `App icon.png` | `app-icon.webp` (+ `.png`), `src/app/apple-icon.png`, `public/icons/*` | App, Apple touch and PWA icons. |

To regenerate after replacing the artwork:

```bash
npm run brand:export   # transparent PNG masters, web logos, favicon.ico, apple/PWA icons, OG image
```

## TLDR Insights feed

`npm run build` runs `scripts/fetch-tldr.mjs` first. That script pulls the five latest issues from:

- TLDR AI: `https://tldr.tech/api/rss/ai`
- TLDR Dev: `https://tldr.tech/api/rss/dev`

The headlines are baked into the static page. If TLDR is down or rate-limits the request, the previously saved `src/data/tldr.json` is used and the build still succeeds. To keep the feed fresh, the site is **rebuilt daily** (see the deploy options below). Run `npm run feed` to refresh it by hand.

## Google Analytics

GA4 loads only when `NEXT_PUBLIC_GA_ID` is set at build time, through `@next/third-parties`.

1. In Google Analytics, create a GA4 property and a **Web** data stream for `https://tailwinds.cloud`, then copy its Measurement ID (`G-XXXXXXXXXX`).
2. To test locally, copy `.env.example` to `.env.local` and fill in the ID.
3. For GitHub Pages, add a repository **variable** (not a secret) named `GA_MEASUREMENT_ID`: Settings → Secrets and variables → Actions → Variables.

## Deploying

The build output in `./out` is plain static files, so either host works.

### Option A: GitHub Pages (workflow included)

`.github/workflows/deploy-pages.yml` builds and deploys on every push to `main`, **daily at 13:30 UTC** (to refresh TLDR), and on demand.

1. Push this repo to GitHub, then go to Settings → Pages → Source and choose **GitHub Actions**.
2. `public/CNAME` already contains `tailwinds.cloud`. At your DNS provider, add:
   - `A` records for `@` pointing to `185.199.108.153`, `185.199.109.153`, `185.199.110.153` and `185.199.111.153`
   - a `CNAME` record for `www` pointing to `<your-github-user>.github.io`
3. In Settings → Pages, set the custom domain and tick **Enforce HTTPS**.

> GitHub pauses scheduled workflows after 60 days with no repository activity. If the feed stops updating, re-enable the workflow in the Actions tab.

### Option B: Google Cloud (Firebase Hosting)

`firebase.json` is included and serves `./out` with long-lived caching for hashed assets.

```bash
npm i -g firebase-tools
firebase login
firebase use --add            # pick or create your GCP/Firebase project
npm run build && firebase deploy --only hosting
```

Then add `tailwinds.cloud` under Hosting → Custom domains. For the daily TLDR refresh, use a scheduled GitHub Action, or Cloud Scheduler with Cloud Build, that runs `npm ci && npm run build && firebase deploy`.

A Cloud Storage bucket behind a load balancer also works. Upload `./out` and set the bucket's main page to `index.html` and its error page to `404.html`.
